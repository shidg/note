# ✅ 一、国家电网体系里：Linux 运维工程师到底是干什么的？

电网体系的 IT 岗位分为两类：

## **（1）正式员工（编制）岗位**

比较少，主要负责管理与统筹。

## **（2）外包（协力）岗位（占多数）**

真正干活的是外包人员，比如来自：

- 东软
- 中软国际
- 博彦科技
- 文思海辉
- 国网信通
- 国网电科院合作公司
- 软通动力

### 外包人员主要负责：

### **① 运维日常巡检（每天必做）**

- 检查服务器负载、CPU、内存、磁盘
- 检查系统日志（syslog / messages）
- 检查应用服务是否在线
- 检查重要流程是否成功（如采集、入库）

### **② 应用发布（极其重要）**

国家电网内部大部分系统按照 **流程化发布**：

- 变更单（如国网统一运维平台）
- 三员审批（管理员、监理、安全）
- 发布窗口（往往是晚上 22:00 后）
- 需要严格执行 SOP（标准操作步骤）

### **③ 数据库相关运维（不需要深度，但要懂基本操作）**

- Oracle（最常用）
- PostgreSQL
- SQLServer（部分老系统）

你不需要精通数据库，但要会：

- 查看连接
- 备份恢复
- 简单的 SQL 检查

### **④ 服务器系统管理**

国家电网的服务器一般是：

- RHEL / CentOS（最多）
- AIX（老系统）
- Windows Server（部分 SCADA/调度系统）

你需要掌握的内容：

- 用户权限
- SFTP 文件传输
- cron 定时任务
- 日志排查

### **⑤ 中间件运维（关键）**

最常见的是：

- WebLogic（国网大量系统使用）
- Tomcat
- Nginx
- Apache
- MQ（ActiveMQ 或 RabbitMQ）

任务包括：

- 部署 WAR 包
- 修改配置
- 查看线程池、连接池
- 查看 GC 日志

### **⑥ 网络相关**

不需要非常精通网络，但必须知道：

- VLAN / 子网划分
- 二三层结构
- 防火墙端口开放
- 双机热备 / 心跳检测

# ✅ 二、国家电网 IT 项目典型架构（必须熟悉）

国家电网项目偏金融级架构，所以有特点：

### **① 经典三层架构**

- Web 层：Nginx/Tomcat
- Service 层：Java + WebLogic
- DB 层：Oracle RAC

### **② 服务器多为虚拟化**

- VMware ESXi + vCenter
- 部署方式严格流程化

### **③ 日志体系严格**

- 日志集中到 ELK / 日志平台
- 关键操作必须有审计记录（堡垒机审计）

### **④ CI/CD 采用“审批流 + 半自动”**

几乎没有互联网那种全自动发布。

你可以这样描述：

> “电网项目的交付流程是严格审批制：需求→开发→测试→灰度→深夜窗口上线，每个动作都需要变更申请和多级审批。”

这样说非常贴合实际。

# ✅ 三、国家电网外包岗位 Typical 工作流程（你面试时可以直接复述）

下面是一个典型工作日（外包运维的真实流程）：

------

## **【早上 9 点：交接 + 巡检】**

- 查看 Nagios/Zabbix 报警
- 检查昨晚批处理任务（采集/入库流程）
- 检查系统日志
- 查看磁盘、CPU、内存是否异常

示例说法：

> “我们每天有固定的巡检 SOP，重点看 CPU、内存、磁盘、关键进程、应用日志和批处理结果。”

------

## **【白天：处理运维工单】**

工单来源：

- 用户反馈
- 测试环境问题
- 新需求变更
- 批处理修复

------

## **【下午：变更准备】**

- 写变更单
- 提交审批
- 准备发布包、备份、回滚方案

------

## **【晚上 10 点后：发布窗口（重点）】**

外包运维的核心时间。

流程：

1. 开启发布窗口
2. 停应用
3. 备份当前版本
4. 部署新版本
5. 重启服务
6. 验证
7. 确认发布成功
8. 关闭窗口

描述例句：

> “我们项目通常在晚上 10 点到凌晨 2 点是上线窗口，需要严格执行 SOP，每一步都要有截图留档。”

# ⭐ 四、国家电网 Linux 运维工程师常见面试题（附示范答案）

我给你完整来一套真实可用版本：

------

## **1. 你在国家电网项目的主要职责是什么？**

示范回答：

> “主要负责服务器巡检、应用发布、中间件维护以及批处理任务排查。每天按巡检表检查系统资源、应用日志和任务状态。发布遵循审批流程，准备好备份和回滚方案，确保发布窗口内完成上线。还负责 WebLogic、Tomcat 的配置调整和性能监控。”

------

## **2. 你负责的系统架构是怎样的？**

示范回答：

> “典型三层架构：前端 Nginx，应用层基于 WebLogic 和部分 Tomcat，数据库是 Oracle RAC。服务器运行在 VMware 虚拟化平台上，日志集中到 ELK。”

------

## **3. 发布流程你们是怎么做的？**

示范回答：

> “我们严格执行变更流程：提交变更单 → 多级审批 → 准备发布包和回滚方案 → 深夜窗口上线。上线严格按照 SOP 进行，完成后要截图留档、写发布报告。”

------

## **4. 你遇到过哪些典型故障？怎么解决？**

示例：

- Tomcat 卡死（线程池耗尽）
- WebLogic 堆内存不足（OOM）
- Oracle 表空间满了
- 批处理失败（上游数据未到）

示范回答：

> “有一次应用访问缓慢，我先检查 Tomcat 线程池，发现线程数耗尽，通过分析日志定位到数据库慢 SQL，联系 DBA 优化后恢复。”
