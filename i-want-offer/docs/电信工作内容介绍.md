# ✅ 一、电信体系里：Linux 运维工程师到底是干什么的？

完成交付私有化项目 其中包括前期部署 其中调试 后期监控运维

## **（1）正式员工（编制）岗位**

比较少，主要负责管理与统筹。

## **（2）外包（协力）岗位（占多数）**

真正干活的是外包或者生态人员，比如来自：

- 中电金信
- 中电福富
- 北京福富
- 一般都是电信100%控股的子公司
### 外包人员主要负责：

### **① 运维日常（项目必做）**

- 完成环境检查
- 通过自有维护的paas层自动化工具完成部署中间件
- 通过k8s集群完成 数据中心的部署
- 检查部署完成的的中台是否可以正常使用
- 通过python脚本完成自动化测试验证
- 完成项目交付

### **③ 数据库相关运维（不需要深度，但要懂基本操作）**

- mysql8
- DM
- ob
- doris


你不需要精通数据库，但要会：

- 查看连接
- 备份恢复
- 简单的 SQL 检查

### **④ 服务器系统管理**

私有化项目的服务器一般是：

- CTyun（天翼云）
- 麒麟
- centos

你需要掌握的内容：

- 用户权限
- SFTP 文件传输
- cron 定时任务
- 日志排查

### **⑤ 中间件运维（关键）**

最常见的是：

- redis
- zookeeper
- kafka
- ceph
- ELK
- kuboard(可以通过图形化管理K8s提高效率)
- hadoop生态 （可不说,意义不大）
任务包括：

- 部署 WAR 包
- 修改配置
- 查看线程池、连接池
- 查看 GC 日志

### **⑥ 网络相关**

不需要非常精通网络，但必须知道：

- VLAN / 子网划分
- 二三层结构
- 防火墙端口开放
- 双机热备 / 心跳检测

# ✅ 二、电信 IT 项目典型架构（必须熟悉）


中电信项目偏私有化

### **① 经典三层架构**

- Web 层：Nginx/Tomcat
- Service 层：Java + WebLogic
- DB 层：Oracle RAC

### **② 服务器多为裸金属**

- 麒麟等国产
- 部署方式严格流程化

### **③ 日志体系严格**

- logstash收集spark flink提交到yarn生成的日志 返回到中台的日志中心 存储到ceph中

### **④ CI/CD 采用“审批流 + 半自动”**

几乎没有互联网那种全自动发布。

你可以这样描述：

> “电信项目的交付流程是严格审批制：需求→工勘→部署→验证功能→完成交付，每个动作都需要变更申请和多级审批。”

这样说非常贴合实际。

# ✅ 三、电信外包岗位 Typical 工作流程（你面试时可以直接复述）

下面是一个典型工作日（外包运维的真实流程）：

------

## **【早上 9 点：交接 + 巡检】**

- 查看 Nagios/Zabbix 报警
- 检查昨晚批处理任务（采集/入库流程）
- 检查系统日志
- 查看磁盘、CPU、内存是否异常

示例说法：

> “我们每天有固定的巡检 SOP，重点看 CPU、内存、磁盘、关键进程、应用日志和批处理结果。”

------

## **【白天：处理运维工单】**

工单来源：

- 用户反馈
- 测试环境问题
- 新需求变更
- 批处理修复

------

## **【下午：变更准备】**

- 写变更单
- 提交审批
- 准备发布包、备份、回滚方案

------

## **【晚上 10 点后：发布窗口（重点）】**

外包运维的核心时间。

流程：

1. 开启发布窗口
2. 停应用
3. 备份当前版本
4. 部署新版本
5. 重启服务
6. 验证
7. 确认发布成功
8. 关闭窗口

描述例句：

> “我们项目通常在晚上 10 点到凌晨 2 点是上线窗口，需要严格执行 SOP，每一步都要有截图留档。”

------

# ⭐ 四、中电信 Linux 交付运维工程师常见面试题（附示范答案）

我给你完整来一套真实可用版本：

------

## **1. 你在电信项目的主要职责是什么？**

示范回答：

> “1.主要负责和前场对接私有化项目所需要的基本环境要求
   2.环境达到要求有完成环境工勘符合条件后 安排生态部署人员完成部署
   3.解答一线部署遇到的问题，如中间件问题 部署流程问题
   3.如一线遇到中间件或产品bug 完成协调paas老师或研发老师解决bug
   4.完成产品的功能验证”

------

## **2. 你负责的系统架构是怎样的？**

示范回答：

> “除中间件服务外 全部运行为k8s容器的方式”

------

## **3. 发布流程你们是怎么做的？**

示范回答：

> “我们严格执行变更流程：提交变更单 → 多级审批 → 准备发布包和回滚方案 → 深夜窗口上线。上线严格按照 SOP 进行，完成后要截图留档、写发布报告。”

------

## **4. 你遇到过哪些典型故障？怎么解决？**

示例：

- k8s svc无法正常解析
- 内存不足（OOM）
- 高可用harbor 脑裂数据不同步
- k8s cocai网卡与宿主机网络不通


示范回答：

> “有一次应用访问缓慢，我先检查 Tomcat 线程池，发现线程数耗尽，通过分析日志定位到数据库慢 SQL，联系 DBA 优化后恢复。”s
